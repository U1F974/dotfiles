# Трей в меню быстрых настроек: описание

Дата: 2026-10-22. Расширение GNOME Shell для этого репозитория (dotfiles,
GNOME 48, Void Linux, Wayland).

## Зачем

В GNOME нет трея приложений. Значки Telegram, Vesktop и подобных программ
нужны: по ним видно статус (непрочитанное), по клику открывается окно,
по правому клику - меню приложения. Готовые расширения ставят значки в
верхнюю панель; хочется держать их внутри меню быстрых настроек, чтобы
панель оставалась чистой, и при этом не пропускать новые сообщения.

Успех: значки всех запущенных приложений с треем видны строкой внизу меню
быстрых настроек, все три действия (клик, меню, статус) работают, а когда
Telegram зовет, его значок сам появляется в панели.

## Что делаем

1. **Хост трея.** Расширение само реализует протокол StatusNotifierItem
   (SNI): занимает на сессионной шине имя `org.kde.StatusNotifierWatcher`,
   принимает регистрации значков и показывает их. Меню значков - по
   протоколу DBusMenu (`com.canonical.dbusmenu`). Чужие расширения (AppIndicator
   и подобные) не нужны и не используются.
2. **Строка значков внизу меню быстрых настроек** (вариант A из макетов):
   отдельная полоса под плитками, сверху отделена линией, на всю ширину меню.
   Если значков нет, строка скрыта целиком.
3. **Значок:**
   - показывает текущую иконку приложения и обновляется вместе с ней;
   - левый клик: `Activate(x, y)` (обычно показать окно); если у элемента
     `ItemIsMenu = true` - открыть меню;
   - правый клик: меню приложения всплывает у значка (DBusMenu по свойству
     `Menu`; если `Menu` нет - вызвать `ContextMenu(x, y)`);
   - средний клик: `SecondaryActivate(x, y)`;
   - колесо: `Scroll(delta, orientation)`;
   - подсказка при наведении: заголовок подсказки (`ToolTip`), иначе `Title`,
     иначе `Id`.
4. **Сигнал в панели.** Когда приложение "зовет", его значок временно
   появляется в верхней панели рядом с индикаторами быстрых настроек.
   Клик по нему работает так же, как по значку в строке трея. Когда
   приложение перестает звать, значок из панели пропадает.

   Приложение зовет, если выполнено любое из условий:
   - `Status == "NeedsAttention"` (так по протоколу);
   - имя иконки (`IconName`) содержит `attention`.

   И не зовет никогда, если имя иконки содержит `mute` (приглушенные чаты
   Telegram). Значки, которые сообщают о непрочитанном только картинкой
   (Vesktop), сигнала не дают - это осознанно.
5. **Вид** как у остальной темы: квадраты 28px, скругление 3px, без фона;
   при наведении фон `currentColor` 8%, при нажатии 16%.

## Чего не делаем

- Старый трей XEmbed (Steam, Wine, GTK2-приложения).
- Окно настроек расширения.
- Ручное скрытие, закрепление или переупорядочивание значков.
- Постоянные значки трея в панели: в панели только сигнал.
- Распознавание непрочитанного по картинке иконки.

## Чего нельзя допустить

- Падение или зависание GNOME Shell из-за приложения. Все вызовы D-Bus к
  приложениям асинхронные с таймаутом; ошибка или молчание одного
  приложения скрывает только его значок, остальные работают.
- Конфликт с другим хостом трея. Если имя `org.kde.StatusNotifierWatcher`
  уже занято (включили AppIndicator), расширение не ломается: строка трея
  не показывается, в журнал пишется понятное сообщение. Когда имя
  освобождается, расширение может его занять (на усмотрение исполнителя).
- Утечки после выключения расширения (`disable()`): все сигналы отписаны,
  имя на шине освобождено, актеры удалены. После десятка циклов
  `gnome-extensions disable/enable` поведение должно быть таким же, как
  после первого.
- Потеря значков после блокировки экрана. *Решение мое:* расширение
  объявляет `session-modes: ["user", "unlock-dialog"]` и при блокировке не
  выключается. Часть D-Bus (имя на шине, зарегистрированные значки) живет
  всегда; интерфейс (строка в меню, значки в панели) скрывается на экране
  блокировки и возвращается после разблокировки (по `Main.sessionMode`).
  Так значки не зависят от того, умеют ли приложения регистрироваться
  заново.

## Проверенные факты (снято тестовым хостом 2026-10-22)

| Приложение | Как регистрируется | Иконка | Статус |
|---|---|---|---|
| Telegram 7.0.4 (Qt) | имя шины, путь `/StatusNotifierItem`, меню `/MenuBar` | `IconName` из темы (`org.telegram.desktop-symbolic`) плюс `IconPixmap` 16x16 и 64x64 | всегда `Active` |
| Vesktop 1.6.7 (Electron 43) | путь объекта `/org/chromium/StatusNotifierItem/1`, меню `/org/chromium/DbusMenu/1` | PNG-файл: `IconThemePath` = временная папка `/tmp/org.chromium.Chromium.*`, `IconName` = `status_icon_N`; при каждой смене новая папка и новое имя, `IconPixmap` пуст | всегда `Active` |

Telegram меняет `IconName`: `...-mute-symbolic` - непрочитанное в
приглушенных чатах, `...-attention-symbolic` - новое сообщение. Vesktop при
непрочитанном рисует красную точку на картинке, имя файла ничего не
говорит.

Отсюда требования к показу иконки: искать `IconName` в теме иконок с
учетом `IconThemePath` (в том числе когда там лежит просто `имя.png`), а
если не найдено - брать `IconPixmap` (ARGB32 в сетевом порядке байт,
выбирать размер, ближайший к нужному с учетом масштаба). Обновляться по
сигналам `NewIcon`, `NewIconThemePath`, `NewStatus`, `NewAttentionIcon`,
`NewToolTip`, `NewTitle`.

`RegisterStatusNotifierItem` получает либо имя шины, либо путь объекта
(Vesktop); во втором случае имя шины - отправитель вызова. Значок
удаляется, когда его имя шины пропадает (`NameOwnerChanged`).

Приложения ищут хост при запуске: Telegram и Vesktop зарегистрировались
только после перезапуска, когда хост уже был на шине. После включения
расширения запущенные до этого приложения появятся, если они следят за
появлением `org.kde.StatusNotifierWatcher` (Vesktop и Telegram при старте
с уже работающим хостом - да; без хоста - не проверено).

## Решения по устройству (приняты)

- Свое расширение в репозитории: `gnome-extensions/local/tray-quick-settings@dots/`,
  uuid `tray-quick-settings@dots`.
- JavaScript (GJS, модули ESM), как требует GNOME 48. Только встроенные
  библиотеки: Gio/GLib для D-Bus, St/Clutter и модули Shell (`quickSettings`,
  `popupMenu`, `panelMenu`) для интерфейса. `metadata.json` с
  `shell-version: ["48"]`.
- В `gnome-extensions/extensions.tsv` новый источник `local`:
  `gnome-extensions/install.sh` ставит такие расширения симлинком папки в
  `~/.local/share/gnome-shell/extensions/<uuid>` и включает, как остальные.
  Подхватывается после повторного входа (Wayland). README (en и ru)
  дополняется.
- Порядок значков в строке - порядок регистрации.
- Значки в состоянии `Status == "Passive"` в строке не показываются
  (протокол разрешает их прятать). *Решение мое, не обсуждалось.*
- Значок-сигнал в панели - один элемент панели (одна роль,
  `tray-attention`) сразу слева от кнопки быстрых настроек, а не элемент
  внутри нее: элемент внутри кнопки быстрых настроек не может принимать
  свои клики. Внутри элемента - по кликабельному значку на каждое
  зовущее приложение; когда никто не зовет, элемент скрыт. Роль
  добавляется в `gnome-extensions/settings/top-bar-organizer.ini` прямо
  перед `quickSettings`, чтобы Top Bar Organizer держал ее там. Меню
  значка в панели - обычное выпадающее меню панели. *Решение мое, не
  обсуждалось.*

- Меню приложения из строки трея (правый клик, или левый при
  `ItemIsMenu`) - отдельное всплывающее меню поверх быстрых настроек,
  рядом со значком (вариант B из макетов, выбран пользователем). Меню
  быстрых настроек при этом остается открытым. Нужно аккуратно
  передать захват ввода (grab) и фокус клавиатуры: меню приложения
  получает клавиши (стрелки, Enter, Esc), Esc или клик мимо закрывает
  только его. *Решение мое:* выбор пункта закрывает и меню приложения, и
  быстрые настройки (как обычное контекстное меню: действие выполнено).

## На усмотрение исполнителя

- Внутреннее устройство модулей, имена классов, файловая структура
  расширения.
- Как именно встроить строку в меню быстрых настроек (элемент
  `QuickSettingsMenu` на две колонки или другой способ), если результат
  выглядит как описано.
- Поддержка дополнительного имени `org.freedesktop.StatusNotifierWatcher`.
- Как отображать `OverlayIcon`, значки пунктов меню, флажки и радиокнопки
  в меню.
- Способ проверки: вложенный сеанс `dbus-run-session gnome-shell --devkit`,
  ручной список проверок с Telegram и Vesktop, тест циклов
  включения/выключения через `gnome-extensions disable/enable`.
